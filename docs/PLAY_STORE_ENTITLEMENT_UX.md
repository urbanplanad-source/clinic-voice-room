# Play Store 체험·구독 UX 계약

## 현재 마일스톤

세 가지 Play 기능 플래그가 기본값 `off`인 동안 기존 웹·Android 화면과 동선은 그대로 유지한다.
스키마가 추가됐다는 이유만으로 구독 배지, 체험 타이머, 결제 버튼 또는 차단 화면을 노출하지 않는다.
클라이언트는 환경변수를 직접 읽지 않고, 이후 서버가 반환하는 권한 상태와 허용된 작업만 표시한다.

## 상태별 사용자 경험

| 상태 | 통역 기능 | 기본 안내 | 주요 행동 |
| --- | --- | --- | --- |
| 체험 미시작 | 허용 | 실제 첫 번역 성공 시 24시간 체험이 시작됨 | 통역 시작 |
| 체험 진행 | 허용 | 남은 시간을 과도하게 강조하지 않고 홈에서만 확인 | 통역 계속 |
| 체험 만료 | 차단 | 무료 체험 종료와 복구 방법을 함께 안내 | 구독 시작 |
| 구독 활성 | 허용 | 정상 상태는 작은 배지로만 표시 | 구독 관리 |
| 결제 유예 | 만료 전 허용 | 결제 수단 확인이 필요함을 경고 | 결제 정보 확인 |
| 보류·정지·만료·취소 후 만료 | 차단 | 차단 이유와 구매 복원 경로를 표시 | 구매 복원 |
| grandfathered | 허용 | 일반 직원 화면에는 별도 설명을 노출하지 않음 | 관리자 확인 |

체험 만료 문구:

- 제목: `무료 체험이 종료되었습니다`
- 설명: `통역 기능을 계속 사용하려면 구독을 시작하거나 기존 구독을 복원해 주세요.`
- 주요 행동: `구독 시작`
- 보조 행동: `구매 복원`

로그인, 로그아웃, 구독 구매·복원·관리 화면은 통역 권한이 만료되어도 접근할 수 있어야 한다.
차단 상태에서 단순 오류만 보여주지 말고 항상 복구 행동을 함께 제공한다.

## 화면 배치

### 웹

- 직원 홈 헤더 아래에 작은 상태 카드를 배치한다.
- 정상 구독은 배지 수준으로 축소하고, 만료 임박·유예·차단 상태만 카드로 확장한다.
- 방 생성 버튼은 서버 권한 결과와 함께 실제 `disabled` 상태를 사용한다.
- 차단 이유와 복구 행동은 비활성 버튼 바로 아래에 표시한다.
- 관리자 사용량 표에 병원별 상태를 추가하고 별도 최상위 메뉴는 만들지 않는다.

### Android

- 홈 모드 카드 아래, 로그아웃 영역 위에 상태 카드를 배치한다.
- 방 생성 버튼은 권한이 없을 때 실제 비활성화하고 바로 아래에 복구 문구를 표시한다.
- 로그인, QR 대기, 통역 진행 화면에는 구독 홍보 UI를 삽입하지 않는다.
- 결제·복원은 하나의 명확한 화면 흐름으로 제공하고 새로운 복잡한 설정 메뉴를 만들지 않는다.

## 시각·상호작용 원칙

- 기존 `trust` 파랑과 `mint` 초록을 유지하고 마케팅용 보라·분홍 그라데이션은 사용하지 않는다.
- 정상, 경고, 차단 상태는 색만으로 구분하지 않고 Lucide 또는 Material 아이콘과 텍스트를 함께 사용한다.
- 웹 터치 영역은 최소 44px, Android는 최소 48dp를 확보한다.
- 한 화면의 주요 행동은 하나만 강조하고 구매 복원은 보조 행동으로 둔다.
- 가격과 남은 시간 숫자는 tabular figures를 사용해 갱신 시 레이아웃 이동을 막는다.
- 상태 전환은 150~300ms의 색·투명도 변화만 사용하며 장식성 반복 애니메이션은 사용하지 않는다.
- `prefers-reduced-motion`과 Android 시스템 애니메이션 축소 설정을 존중한다.

## 접근성·오류 처리

- 웹 차단 및 결제 오류는 `role="alert"` 또는 적절한 `aria-live` 영역으로 알린다.
- Android는 `contentDescription`과 Compose semantics로 상태·버튼 목적을 읽을 수 있게 한다.
- 비활성 버튼은 시각적 비활성화와 실제 비활성 semantics를 함께 제공한다.
- 네트워크 지연이 300ms를 넘으면 진행 상태를 표시하고 중복 구매·복원 요청을 막는다.
- 오류 문구는 원인과 다음 행동을 함께 설명한다.

## 활성화 전 확인

- 375px 웹, 작은 Android 휴대폰, 태블릿, 가로 모드에서 잘림 없이 동작하는지 확인한다.
- 밝은 화면과 어두운 화면에서 본문 대비 4.5:1 이상을 확인한다.
- 큰 글꼴과 화면 읽기 순서에서 상태 카드와 행동 버튼이 자연스럽게 이어지는지 확인한다.
- 플래그가 `off`일 때 기존 화면의 렌더링과 API 호출 수가 변하지 않는지 회귀 테스트한다.
