# MediVoice 번역 앱 경쟁 벤치마크

기준일: 2026-08-07

## 평가 범위와 한계

이 문서는 공개된 공식 제품 기능과 현재 MediVoice 구현을 비교한 제품·운영 분석이다. 동일 녹음과 동일 의료 문장으로 블라인드 평가한 결과가 아니므로, 앱별 번역 정확도 순위를 주장하지 않는다. 정확도 비교는 별도의 공통 시험 세트와 언어별 의료 검토자가 필요하다.

평가 기준은 일반 여행 번역 기능 수가 아니라 의료 현장 적합성이다.

- 의료적으로 검증된 문장과 용어
- 숫자, 용량, 횟수, 부정, 질문·명령 방향의 보존
- 오류 발견·수정·승인·롤백
- 연결 장애 때의 안전한 대체 수단
- 한 명씩 말하는 상황의 명확성
- 환자 설치 부담과 접근성
- 개인정보 최소화와 운영 진단
- 언어·진료과별 품질 측정 가능성

## 현재 MediVoice의 상대적 강점

1. 병원 직원 인증, 병원 계정, 시술방, QR 환자 참여와 대면모드가 하나의 임상 흐름으로 연결된다.
2. 환자는 앱을 설치하지 않고 방별 임시 링크로 참여한다.
3. 한국어를 직원 발화의 기준으로 두고 중국어 간체·번체·광둥어를 분리한다.
4. 피부과·성형외과·한의원 데이터셋과 glossary/STT 힌트를 운영 자산으로 만들 수 있다.
5. 숫자·단위·부정·방향·원문에 없는 답변을 검사하고, 잘못된 번역을 같은 차례에서 교정해 화면·TTS·샘플·지표에 반영하는 구조가 있다.
6. 풋페달, USB 마이크, 시술 중 짧은 안내처럼 일반 번역 앱이 다루지 않는 현장 장비와 자세를 고려한다.
7. 원시 음성과 전체 상담 기록을 영구 저장하지 않고, 비식별 품질 지표만 제한적으로 재전송한다.
8. 0.3.38부터 개인정보 없는 현장 진단과 서명·버전·SHA-256 배포 검증이 있다.

## 현재 가장 부족한 부분

### 1. 오프라인 안전망

현재 앱은 온라인 전용이다. 경쟁 앱의 범용 오프라인 번역 전체를 따라갈 필요는 없지만, 네트워크가 끊겨도 사용할 수 있는 의료 검증 문장과 사전 생성 음성은 필요하다.

### 2. 검증 문장 우선 사용이 사용자에게 보이지 않음

내부 즉시 템플릿과 검증 문장이 있어도 직원이 진료과·상황별로 찾아서 재생하는 문구집 화면은 약하다. Care to Translate처럼 검증 문장과 자유 AI 번역을 명확히 구분해야 한다.

### 3. 고위험 문장의 사람 통역 전환

동의, 수술·시술 위험, 알레르기, 약물, 임신, 응급, 퇴원 복약처럼 오역 비용이 큰 상황에서 통역사·병원 담당자에게 전환하는 명확한 동작이 없다.

### 4. 언어별 실제 품질 수치 부재

17개 언어를 지원한다는 것과 17개 언어에서 의료적으로 쓸 수 있다는 것은 다르다. 진료과·언어·화자 방향·위험 유형별 STT, 번역, TTS 성공률과 중대 오류율이 필요하다.

### 5. 환자 확인 UX

숫자, 용량, 날짜, 좌우 부위, 부정 표현은 번역 후 환자에게 다시 확인받는 구조가 필요하다. 현재의 검증과 배지는 출발점이지만, `맞아요 / 다시 말할게요 / 직원 호출` 같은 응답 흐름까지 이어져야 한다.

### 6. glossary 운영 성숙도

glossary와 STT 힌트를 만들고 충돌을 사람 검토할 수 있지만, 활성 버전·배포 대상 병원·진료과 pack·승인자·롤백·앱 적용 버전까지 하나의 감사 흐름으로 묶어야 한다.

### 7. 접근성과 재생 제어

큰 글자, 느린 재생, 문장별 반복, 청각이 약한 환자를 위한 텍스트 고정, 언어별 TTS 제공 여부를 더 명확히 해야 한다.

## 권장 로드맵

### P0: 비공개 현장 시험 전에 필요

1. `검증 문장` 화면을 만들고 피부과·성형외과·한의원 specialty pack을 검색·즐겨찾기·즉시 재생할 수 있게 한다.
2. 검증 문장은 자유 번역보다 먼저 정확히 매칭하고 `의료 검토 완료`를 문구와 아이콘으로 표시한다.
3. 검증 문장·번역·TTS를 일부 핵심 언어부터 오프라인 pack으로 제공한다.
4. 숫자·용량·횟수·날짜·좌우·부정·동의 문장을 고위험으로 분류하고 환자 확인 버튼을 표시한다.
5. 고위험 상황에 `사람 통역 요청` 또는 병원 지정 연락처를 제공한다.
6. 3개 진료과 데이터셋으로 공통 평가 harness를 만들고 언어별 중대 오류율을 release gate에 넣는다.
7. glossary/STT pack에 버전, 승인자, 적용 병원, 적용 진료과, 배포일, 롤백 상태를 추가한다.

### P1: 비공개 시험 중 개선

1. 환자용 탭 응답: `네`, `아니요`, `잘 모르겠어요`, `다시 말씀해 주세요`, `통역사가 필요해요`.
2. TTS 속도 `느리게 / 보통`과 마지막 문장 즉시 반복.
3. 언어 선택 화면에 음성 입력·음성 출력·오프라인 문구 지원 여부 표시.
4. 품질 지표 화면에 언어·진료과·방향·위험도별 오류율과 glossary 수정 효과 표시.
5. 자동 화자 감지는 저위험 대면 상황에서만 실험 옵션으로 평가하고 PTT를 기본으로 유지한다.

### P2: 근거가 쌓인 뒤 검토

1. 동의서·주의사항의 카메라/문서 번역.
2. 그룹 대화와 다자 통역.
3. 선택적 상담 기록 내보내기. 기본은 현재처럼 비저장으로 유지한다.

## 객관적 번역 품질 시험 설계

앱별 정확도를 비교하려면 다음 절차를 사용한다.

1. 피부과·성형외과·한의원에서 언어별 최소 100문장, 총 300문장 이상의 고정 시험 세트를 만든다.
2. 숫자·용량·횟수·날짜·가격·좌우·부정·질문·명령·브랜드·시술명을 층화한다.
3. 동일 휴대폰·동일 거리·동일 녹음 파일을 MediVoice, Papago, Google, Microsoft, DeepL에 입력한다.
4. 앱 이름을 가린 출력물을 언어별 의료 검토자 2명이 독립 평가한다.
5. 단순 자연스러움보다 중대 오류를 크게 가중한다.

권장 지표:

- STT 핵심 토큰 보존율
- 숫자·단위 완전 보존율
- 부정·질문·명령·화자 방향 보존율
- 브랜드·의료 용어 정확도
- 원문에 없는 답변 생성률
- 중대 의료 오류율
- 첫 결과와 TTS 시작까지의 지연
- 재시도·재연결 성공률
- 사람 검토 후 glossary 수정으로 감소한 오류율

## 결론

MediVoice가 Papago나 Google보다 많은 범용 기능을 갖추는 것은 현실적인 목표가 아니다. 경쟁 우위는 `병원 흐름 + 검증 문장 + 진료과 glossary + 고위험 차단 + 사람 검토 + 비식별 학습 루프`에 있다. 가장 먼저 벤치마킹할 제품은 범용 번역 앱보다 Care to Translate이며, 기술 운영 면에서는 DeepL의 glossary 배포와 데이터 보존 통제가 참고 대상이다.
